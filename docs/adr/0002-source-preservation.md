# 0002. 以顶层源码块为保留粒度，用块身份与语义快照决定复用

- 状态：accepted
- 日期：2026-09-09
- 关联：`docs/architecture.md`、`src/source/`

## 背景

需求的核心承诺是：未编辑文档逐字符原样导出，修改一个源码块不重新格式化其他
未修改块。GitLab 返回的 HTML 不包含 Markdown 原文，只通过 `data-sourcepos`
给出位置，且展示层会注入渲染地址、引用标题、锚点等不属于源码的信息。

## 决策

以**顶层源码块**为保留粒度：

- 每块记录 `id`、`from`、`to`、`raw` 与初始语义快照。
- 块身份由 ProseMirror 插件维护：事务后扫描顶层块，已有且未被占用的 ID 保留，
  新增或重复的身份获得新 ID；粘贴内容在 `transformPasted` 阶段清除来源 ID。
- 是否复用原文由**语义快照**决定，快照只包含节点类型、正文、标记与影响导出的
  属性，排除块 ID、展示地址、主题与编辑控件状态。
- 间隔只在相邻块原本相邻且都未修改时复用，否则使用两个默认换行。

## 理由与取舍

考虑过的其他选择：

- **整篇 HTML 反转 Markdown**：会重新格式化全文，违反核心承诺。
- **按文本搜索恢复区间**：重复段落和重复表格会错误匹配。
- **按内容哈希识别块**：重复内容无法区分，且哈希不表达“是否被修改”。
- **逐字符最小差异**：需要完整 Markdown 解析器与差异算法，收益不足。

选择顶层源码块的理由是它在“保真”和“可实现性”之间取得了合适平衡：粒度足够
避免误伤其他块，又不需要自己实现完整 Markdown 解析。

接受的代价：

- 修改表格单元格会重写整个表格，修改列表项会重写整个顶层列表。
- 重新导入（源码模式改动后切回）会建立新基线，旧块的原文不再复用。

## 后果与验证

- 基线必须自校验：按“间隔 + 块原文”拼接后严格等于输入，否则整篇降级为单个
  源码块并在界面说明。
- 验证：`tests/source-preservation.spec.ts` 覆盖原样导出、局部编辑、重复段落与
  重复表格、删除块、降级路径与块身份唯一性。
